# 详细行动计划与 Apple × Anthropic 界面设计

日期：2026-07-28
状态：在用户授权“一切按照推荐方案”后按 autopilot 采用推荐设计

## 1. 问题与目标

当前行动中心已经具备服务端持久化、状态推进、成果提交和教师核验，但主界面把每项行动压缩成标题、短说明与两个按钮。学生仍要自己判断先做什么、怎样开始、做到什么程度才算完成；手动新增行动也只填写标题，容易继续产生模糊任务。

本轮目标不是增加新的生涯测评或扩张后台，而是把已有行动档案变成一份真正可执行的个人计划：

- 首屏明确当前进度、当前焦点和下一次点击。
- 每项行动能回答“为什么现在做、分哪几步、要留下什么成果、什么时候完成”。
- 详细信息采用渐进披露，默认界面保持安静、清楚，不堆砌说明。
- 手动行动必须填写任务说明，并可选择分类和截止日。
- AI 生成的行动说明包含顺序明确的执行步骤和可核验完成标准。
- 保留现有服务端数据结构、成果核验语义和邀请制试点边界。

## 2. 方案比较与决定

### 方案 A：只重做卡片视觉

放大标题、调整颜色与间距，不改变行动内容。风险低，但无法解决计划不够具体的问题。

### 方案 B：扩展数据库行动 schema

为每项行动新增步骤、预计时长、成功标准和子任务状态字段。表达能力最强，但会引入数据库迁移、远端发布脚本改造、旧数据回填和额外状态机；对本轮目标而言成本过高。

### 方案 C：渐进式执行蓝图（采用）

保留现有 `ActionItem` 服务端契约，把已有标题、说明、分类、来源、状态和截止日转换为稳定的展示模型；为不同分类提供清楚标注为“建议”的三步执行框架和完成标准。AI 任务在生成时把真实步骤与产出写入现有说明字段，手动新增则直接采集详细说明。

该方案能让旧行动立即受益，不伪造用户已经完成的事实，不需要数据库迁移，也不干扰当前未提交的生产部署改动。

## 3. 信息架构

行动中心按四层组织：

1. **页面导语**：说明这里用于安排、推进和留下证据。
2. **计划概览**：展示总行动数、进行中、待核验、已完成，以及整体进度。
3. **本周焦点**：从待补充、进行中、临近截止和待开始行动中选择唯一优先项，给出主操作。
4. **完整计划**：继续按成长路径分组；每张卡先显示状态、标题、说明和日期，展开后显示执行蓝图、完成标准与相关操作。

页面末尾提供“添加自己的行动”。表单默认保持紧凑，展开后填写：

- 行动名称（必填）
- 具体说明（必填）
- 行动类型（必填，默认实践）
- 截止日期（可选）

## 4. 交互设计

### 4.1 焦点行动

焦点优先级为：

1. 教师退回待补充
2. 已在进行中
3. 七天内到期
4. 其他待开始

已提交待核验和已完成行动不进入焦点。焦点卡主按钮沿用现有状态机：待开始时为“开始行动”，进行中时为“标记完成”，待补充时为“补充成果”。如为校内资源行动，保留“查看资源”入口。

### 4.2 行动卡

行动卡采用原生 `details/summary` 渐进展开，键盘和触控均可访问：

- 摘要层：序号、状态、分类、来源、截止日、标题、原始说明。
- 展开层：建议投入、三步执行蓝图、完成标准、成果提交或资源入口。
- 状态色只作为辅助，所有状态同时保留文字。
- 已完成行动降低视觉权重，但不隐藏反思。

建议步骤来自行动分类和当前状态，只表示执行方法，不表示用户已经完成任何子步骤。原始行动说明始终保留为权威内容。

### 4.3 手动新增

不再为只输入标题的行动自动生成“完成后记录成果或发现”作为唯一说明。用户必须填写具体说明；服务端现有校验继续作为最终边界。创建成功后，新行动立即进入当前分组和焦点排序。

### 4.4 AI 计划

保持现有 JSON 契约，不新增后端字段。规划提示词要求：

- `detail` 按准备、执行、整理三个动作写成有顺序的具体说明；
- `evidence` 必须是可核验的产出或判断标准；
- 不生成访谈、约谈或联系从业者任务；
- 不制造不存在的课程、证书或校内机会。

保存到行动中心时，把完成标准合并进现有任务说明，避免经过服务端导入后丢失。

## 5. 组件与边界

### `src/services/actionPlan.ts`

纯函数展示层，负责：

- 焦点行动排序；
- 日期和来源标签；
- 按分类生成建议投入、三步执行框架和完成标准；
- 输出稳定、可单测的 `ActionPlanPresentation`。

它不访问网络、不修改状态，也不宣称建议步骤已完成。

### `src/components/product/ActionPlanCard.tsx`

只负责单张行动卡的渐进展示和按钮事件。通过明确的 props 接收 `action`、序号、状态推进、成果提交和资源跳转能力，不自行请求 API。

### `src/pages/RoadmapPage.tsx`

继续负责加载、导入、创建、更新和成果提交；新增概览计算、焦点选择与详细新增表单。页面不复制展示规则。

### `server/planner.mjs` 与 `src/pages/AiPlanningPage.tsx`

只增强任务说明的具体程度与保存时的内容保留，不改变接口路由和 JSON 顶层结构。

## 6. 数据流

```text
规则 / AI / 校内资源 / 手动新增
              ↓
        现有 ActionItem API
              ↓
  RoadmapPage 加载服务端权威行动
              ↓
 actionPlan 纯函数生成展示蓝图
              ↓
 焦点行动 + 可展开行动卡 + 成果提交
```

状态更新仍通过现有 `PATCH /me/actions/:id`；成果仍通过 `POST /me/evidence`，教师核验和能力画像逻辑不变。

## 7. 视觉系统

采用“Apple 的空间纪律 + Anthropic 的编辑感”：

- 使用现有系统字体栈，保证 Windows 与 Apple 设备都清晰；不下载外部字体。
- 背景为暖米白，内容面为纸张白，正文为深棕黑。
- 陶土橙只用于焦点、进度和主要反馈，不作为大面积装饰。
- 24px 左右圆角、1px 暖灰边框、低对比阴影，减少玻璃化和强渐变。
- 标题大而克制，元数据使用紧凑等宽标签，正文保持舒适行高。
- 桌面焦点卡使用左右分栏；移动端变为单列，所有点击目标至少 44px。
- 深色主题、减少动效、减少透明度和 200% 缩放保持可读，不依赖 hover 才能操作。

## 8. 异常与边界

- 加载失败：保留现有可见错误信息，不展示伪造计划。
- 新增失败：保留用户已输入内容，显示服务端错误。
- 更新失败：不乐观修改本地状态，继续显示原状态。
- 没有行动：继续引导低年级进入方向探索、高年级进入目标诊断。
- 没有截止日：显示“待安排”，不虚构日期。
- AI 未配置或调用失败：规则计划仍可用，页面不阻塞。
- 旧行动说明较短：展示分类建议步骤，但明确标注“建议执行”。

## 9. 验收与测试

### 自动化

- `actionPlan` 纯函数单测覆盖焦点排序、截止日、分类蓝图和无日期状态。
- Planner 单测断言提示词要求分步说明，现有结构校验和访谈禁用规则继续通过。
- E2E 覆盖：
  - 行动中心出现概览与本周焦点；
  - 行动卡可展开并看到三步执行与完成标准；
  - 手动新增必须填写详细说明，分类和截止日可保存；
  - 移动端无水平溢出。
- 完整运行 `npm run check:release`。

### 视觉

- 1440px 桌面：焦点层级清楚，行动列表不过密。
- 390px 与 360px 手机：单列、44px 触控目标、无横向溢出。
- 深色、减少动效和 200% 缩放：内容不遮挡，展开卡可操作。
- 使用现有视觉审计输出截图并人工检查行动中心桌面与移动端。

## 10. 非目标

- 不新增数据库 schema 或子任务完成状态。
- 不改教师核验规则、能力评分、通知或资源发布流程。
- 不自动替用户标记任何建议步骤为完成。
- 不接入新的外部数据源，不把 AI 作为完成判定者。
