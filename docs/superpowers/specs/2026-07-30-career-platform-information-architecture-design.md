# 职业规划平台统一信息架构设计

日期：2026-07-30
目标分支：`codex/detailed-action-plan`
状态：设计已确定，待实施

## 1. 背景

当前学生端已经形成完整业务能力：方向探索、岗位诊断、AI 个性化规划、培养方案学习路径、校内资源、行动计划、成果核验、七维能力画像、通知和个人资料。问题不在功能缺失，而在功能增长后仍沿用“一个能力一张页面”的组织方式：

- 工作台与行动中心都在展示当前重点；
- 目标诊断、AI 规划和学习路径都在生成行动计划；
- 校内资源与行动中心分别管理行动来源和行动执行；
- 岗位差距、能力画像和研究生成果证据都在解释能力；
- 同一类主要操作在教师端不同区域重复出现。

用户需要先理解系统结构，才能决定去哪里完成任务。移动端虽然已经能访问全部功能，但“更多”菜单仍暴露了产品内部模块划分，而不是用户当前要完成的事情。

## 2. 设计目标

1. 学生端一级导航从功能列表收敛为四个任务工作区：今天、规划、行动、成长。
2. 每类用户任务只有一个权威入口；其他页面只提供上下文链接，不重复实现完整流程。
3. 保留现有业务数据、API、权限、深链接和功能，不进行数据库迁移。
4. 桌面端与移动端使用同一信息架构，只改变导航呈现和内容密度。
5. 教师端继续使用一个工作台，以标签页区分总览、资源、成果核验和学院洞察。
6. 保持暖米白、纸张白、深棕黑和陶土橙的视觉系统，统一标题、卡片、标签、状态和主要操作层级。

## 3. 非目标

- 不新增新的职业测评、模型评分或数据源。
- 不改变 DeepSeek、行动、资源、成果核验和能力合成的服务端契约。
- 不把教师功能并入学生工作区。
- 不在本轮引入新的路由框架、状态管理库或数据库 schema。
- 不删除旧路由；旧链接继续可访问或跳转到新工作区的准确位置。

## 4. 方案比较

### 方案 A：只重新分组导航

保留所有页面，仅把侧栏和移动菜单按“规划、行动、成长”分组。

优点是改动小、回归风险低。缺点是工作台与行动中心、诊断与 AI 规划、资源与行动仍然重复，用户只是更容易找到重复页面。

### 方案 B：单页超级工作台

把所有功能收进一个页面，用折叠区和弹窗呈现。

优点是入口最少。缺点是页面过长、状态复杂、深链接和移动端操作变差，也会让一个组件承担过多职责。

### 方案 C：四个任务工作区（采用）

建立“今天、规划、行动、成长”四个稳定入口，每个工作区内部用标签或阶段导航组织相关功能。现有功能组件迁移到明确边界内，旧路由兼容。

该方案能真正消除重复入口，同时保持组件独立、深链接可用和实施风险可控。

## 5. 新信息架构

### 5.1 学生端一级导航

| 工作区 | 用户问题 | 主要内容 | 不承担的职责 |
| --- | --- | --- | --- |
| 今天 | 我现在最该做什么？ | 三项优先事项、截止与反馈、当前计划状态、快捷继续 | 不展示完整任务列表，不重新生成计划 |
| 规划 | 我要往哪里走，如何安排？ | 目标方向、差距诊断、培养方案学习路径、AI 辅助生成 | 不推进任务状态，不提交成果 |
| 行动 | 我有哪些任务和机会，如何完成？ | 本周、全部行动、校内资源、手动新增、成果提交与复盘 | 不重新解释职业方向和完整能力画像 |
| 成长 | 我积累了什么，判断有多可信？ | 七维能力、证据可信度、成果摘要、个人学习背景入口 | 不生成行动计划，不发布校内资源 |

通知不再占一级导航。顶部保留通知按钮和未读数量，进入独立通知页；通知页仍可通过原路由访问。

个人资料不再作为学生主流程一级入口。顶部账号菜单提供“个人资料、调整画像、退出登录”，成长工作区提供学习背景入口。

### 5.2 教师端一级结构

教师端保持单一路由 `/teacher/dashboard`，内部四个标签：

1. 总览：待处理数量、运行指标、最近资源；
2. 资源：草稿、审核、发布、关闭和归档；
3. 成果核验：匿名成果队列和统一量表；
4. 学院洞察：达到阈值后的匿名群体统计。

“新建资源”只在资源标签的页面工具栏中出现。总览的待处理按钮切换到对应标签，不重复创建操作。

## 6. 学生工作区详细布局

### 6.1 今天

今天页由四层组成：

1. 紧凑问候与日期；
2. “下一步”主卡，只显示一项最高优先行动和唯一主要按钮；
3. 另外两项待处理事项，以紧凑列表呈现；
4. 三个状态摘要：规划是否确定、行动进度、成长可信度。

当前 `StudentHomePage` 的四个大快捷卡改为三个紧凑工作区入口。行动中心的“本周焦点”不再单独重复展示；今天页链接到行动详情，行动页只负责执行。

### 6.2 规划

规划工作区使用页面内阶段导航：

- 方向：低年级使用六步探索，高年级使用目标路径和岗位诊断；
- 学习：培养方案导入、课程差距和学习路径；
- 生成：规则计划与可选 AI 辅助。

三个阶段共享一条“当前规划摘要”，包括阶段、目标路径、目标岗位、学习路线和最近生成时间。任一阶段更新后，摘要同步变化。

AI 不再作为独立产品入口。它作为“生成”阶段的增强方式：规则建议始终可用，DeepSeek 就绪时可生成更细的方向和行动。学习路径中的“加入行动中心”和诊断中的“生成路线图”仍保留，但保存后统一进入行动工作区。

低年级六步探索和高年级岗位诊断保留各自独立组件与权限。规划工作区只负责组合和导航，不把两套业务逻辑混在一个组件中。

### 6.3 行动

行动工作区使用四个标签：

- 本周：按截止、退回、进行中和待开始排序；
- 全部：完整行动列表、筛选、展开执行蓝图；
- 找资源：嵌入校内资源发现和参与流程；
- 新增：手动行动表单。

“本周焦点”只在今天页展示。行动页顶部使用紧凑进度条和状态筛选，不再放置第二张大型焦点卡。

资源加入后直接生成或关联服务端权威行动；资源卡显示参与状态，行动详情显示来源。成果提交、反思、教师退回和核验都从行动详情进入，避免用户在资源页与行动页之间猜测下一步。

### 6.4 成长

成长工作区由三部分组成：

1. 可信度摘要：低、中、高及形成原因；
2. 七维能力：自评、当前画像、核验证据数量；
3. 成果与背景：最近核验成果摘要、学习背景和个人资料入口。

岗位诊断页不再重复完整七维能力说明，只展示与当前目标最相关的三项差距，并链接到成长工作区的对应维度锚点。

研究生页面中的成果证据映射保留在研究生规划组件中，但只展示本次双线计划相关的简要结果；完整能力趋势回到成长工作区。

## 7. 路由与兼容策略

新增稳定路由：

- `/student/today`
- `/student/plan`
- `/student/plan?section=direction`
- `/student/plan?section=learning`
- `/student/plan?section=generate`
- `/student/actions`
- `/student/actions?section=week`
- `/student/actions?section=all`
- `/student/actions?section=resources`
- `/student/actions?section=new`
- `/student/growth`

兼容映射：

| 旧路由 | 新位置 |
| --- | --- |
| `/student/home` | `/student/today` |
| `/student/awakening` | `/student/plan?section=direction` |
| `/student/matching` | `/student/plan?section=direction` |
| `/student/learning-path` | `/student/plan?section=learning` |
| `/student/ai-planning` | `/student/plan?section=generate` |
| `/student/roadmap` | `/student/actions?section=all` |
| `/student/opportunities` | `/student/actions?section=resources` |
| `/student/abilities` | `/student/growth` |

第一阶段不删除旧页面组件。旧路由渲染相同工作区并选中对应 section，确保书签、通知链接和已有测试不会失效。路由组件通过查询参数决定当前标签，并在切换时更新 URL，支持刷新和分享。

研究生主入口仍为 `/graduate/navigation`，但主导航使用同样的“今天、规划、行动、成长”语言。研究生的规划入口落到双线计划，行动入口落到共享资源与行动，成长入口落到共享能力画像。

## 8. 组件边界

新增组合层组件：

- `StudentTodayWorkspace`：只组合优先事项和状态摘要；
- `PlanningWorkspace`：管理 section 路由和共享规划摘要；
- `ActionWorkspace`：管理本周、全部、资源和新增标签；
- `GrowthWorkspace`：组合能力、成果摘要和背景入口；
- `WorkspaceTabs`：桌面与移动共用的可访问标签组件；
- `AccountMenu`：通知、个人资料、调整画像和退出；
- `PlanSummary`：规划工作区共享摘要；
- `ActionDetailPanel`：统一成果提交、反思和来源展示。

现有业务组件继续负责单一能力：

- `AwakeningPage` 的六步探索逻辑提取为方向组件；
- `MatchingPage` 的岗位筛选与差距诊断提取为高年级方向组件；
- `LearningPathPage` 的培养方案和拓扑逻辑提取为学习组件；
- `AiPlanningPage` 的两阶段生成逻辑提取为生成组件；
- `OpportunityBoardPage` 的资源卡与参与状态作为行动资源标签；
- `RoadmapPage` 的任务列表和新增表单作为行动标签；
- `AbilityProfilePage` 的自评和可信度作为成长核心。

组合层不复制业务状态，也不直接调用重复 API。数据继续通过现有 Zustand store 和 API 模块流动。

## 9. 统一视觉规则

### 9.1 页面层级

- 每个工作区只保留一个页面主标题；
- 工作区标签位于标题下方，桌面为横向标签，移动为等宽分段控件；
- 每个 section 只允许一个主要操作按钮；
- 状态摘要使用小卡，任务与资源使用同一列表卡骨架；
- 深色大卡只用于“下一步”或关键诊断，不在同一屏重复出现。

### 9.2 组件语言

- 主要按钮：深棕底、纸白字；
- 次要按钮：透明或浅陶土色；
- 状态标签统一为待开始、进行中、待补充、待核验、已完成；
- 卡片圆角、边框、内边距由统一 token 控制；
- 标题使用宋体编辑感，操作和数据使用系统无衬线字体；
- 图标只用于识别，不承担隐藏文字含义。

### 9.3 响应式规则

- 720px 以下底栏固定为“今天、规划、行动、成长”四项，不再使用“更多”承载核心功能；
- 向下阅读自动收起、向上滚动恢复的行为保留；
- 工作区内部标签完整显示，不使用无提示的横向裁切；
- 表单、任务、资源和能力卡单列；
- 培养方案拓扑继续使用纵向 11 步列表；
- 主要按钮最小高度 44px，并预留底部安全区。

## 10. 数据流与状态

1. 画像和学习背景仍由现有账户状态保存；
2. 方向探索、岗位诊断、AI 规划和学习路径继续更新各自现有状态；
3. 生成或导入行动时继续写入现有 `roadmapTasks` 和服务端行动；
4. 资源参与继续由资源 API 管理，并通过已有 source/sourceId 与行动关联；
5. 成果提交和教师核验继续更新服务端证据与能力画像；
6. 工作区 section 属于 URL 状态，不持久化到数据库；
7. 页面切换不重置表单或已生成结果。

## 11. 错误、空状态与权限

- AI 未配置：生成标签显示规则方案，DeepSeek 区域明确降级，不阻塞规划；
- 没有培养方案：学习标签允许使用通用路径；
- 没有行动：行动页提供“去规划”和“手动新增”两个清晰入口；
- 没有匹配资源：保留筛选和匿名需求说明；
- 没有核验证据：成长页显示自评起点和如何获得可信证据；
- 教师权限不足：不展示对应标签和操作，不只依赖禁用按钮；
- section 参数无效：回退到该工作区默认标签；
- API 失败：保留本地状态时明确提示同步失败，不伪装成功。

## 12. 测试策略

### 12.1 单元测试

- 旧路由到新 section 的映射；
- 学生阶段对应的规划 section；
- 行动来源与状态筛选；
- section 参数非法回退；
- 工作区摘要从现有状态派生，不产生第二份状态。

### 12.2 浏览器流程

- 高年级：规划方向 → 生成计划 → 行动执行 → 提交成果 → 成长画像；
- 低年级：六步探索 → 生成行动 → 今天页继续；
- 培养方案：导入 → 查看路径 → 加入行动；
- AI：服务就绪和未配置两种路径；
- 资源：发现 → 加入 → 报名 → 提交 → 教师核验；
- 旧深链接打开后定位到正确工作区标签；
- 移动底栏四项都可达，切换后 URL 与标题正确；
- 教师端四个标签和新建资源唯一入口。

### 12.3 视觉验收

覆盖 1440、1024、390 和 360 像素，浅色、深色、减少动效和 200% 缩放。每个工作区至少一个桌面和移动截图，并检查：

- 无水平溢出；
- 主要操作不被底栏遮挡；
- 同一屏不出现两个竞争性的主要按钮；
- 标题、卡片、标签和状态样式一致；
- 空状态和错误状态仍能找到下一步。

## 13. 实施顺序

1. 建立路由映射、工作区壳层和共享标签组件；
2. 重构今天页，移除重复大型快捷入口；
3. 组合规划工作区，保持原有方向、学习和 AI 业务组件；
4. 组合行动工作区，统一任务、资源、新增和成果入口；
5. 组合成长工作区，收敛能力和背景入口；
6. 调整教师端重复操作；
7. 统一视觉 token 和响应式规则；
8. 更新 E2E、视觉审计和旧路由兼容测试；
9. 运行完整发布门禁并进行生产子路径构建验证。

## 14. 验收标准

- 学生端主导航只有今天、规划、行动、成长四项；
- 目标诊断、AI 规划和学习路径不再作为三个并列一级入口；
- 校内资源与行动计划在同一行动工作区；
- 工作台与行动页不再重复大型本周焦点；
- 教师端“新建资源”只有一个权威入口；
- 所有旧路由定位到正确的新工作区和标签；
- 现有功能、权限、数据和 API 契约保持完好；
- 完整发布门禁通过，新增主流程 E2E 和视觉场景通过；
- 390px、360px 和 200% 缩放无横向溢出，主要操作可见可用。
